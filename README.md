# «Что поесть» — лендинг Кристины Василиу (vas_kristi)

Живая версия: https://vaskristi.ru/ — сервер 176.53.239.107 (Selectel), nginx, сайт в `/var/www/vaskristi.ru` (клон ветки `landing-v1`). После пуша обновить сайт на сервере: `ssh root@176.53.239.107 deploy-vaskristi-ru`. Копия на GitHub Pages: https://sergeykutedesign.github.io/KRV/.

Статичный сайт: `index.html` + `assets/`. Локально достаточно `python -m http.server 5173`.

- **`tools/typograph.py`** — после правки текстов: `python tools/typograph.py`. Ставит неразрывные пробелы прямо в `index.html` (в конце строки не висят «и», «в», «для», «или»…, тире не уходит в начало строки, «13 кг» не рвётся). В `main.js` та же логика страхует текст, который появляется из JS.
- **`tools/build.py`** — запускается при деплое на сервере, в репозитории ничего не меняет: встраивает CSS в HTML (первый экран рисуется без отдельного запроса за стилями) и ставит метку версии `?v=<коммит>` у файлов.

## Позиционирование

- **Зачем приходят:** за фигурой.
- **Почему раньше не получалось:** не из-за силы воли, а из-за усталости каждый день решать «что поесть» → срывы.
- **Что продаём:** систему, которая убирает это решение: 1,5–2 часа у плиты — еда на 3 дня, КБЖУ и список продуктов готовы.
- **Главное сообщение:** «Забудь о вечном „Что поесть?“».

Правила текста (от дизайнера): человек смотрит лендинг 1–2 минуты. Блок — это «крючок + пояснение», подзаголовок — одно короткое предложение, не больше 3 строк. Цифры живут внутри преимуществ («60+ рационов»). Всё длинное — в FAQ.

## Сценарий страницы

1. **Hero.** Над заголовком — плашка «Закрытый Telegram-канал · 4 600+ участниц» (сразу понятно, что это и где). Кадр из видео виден мгновенно, само видео грузится после загрузки страницы и проявляется поверх. При скролле видео сжимается в карточку, по бокам выплывают стикеры (1,5 часа · −13 кг · 0 подсчётов · Десерты), карточка улетает вверх, за ней — «Представь: больше не нужно думать, что приготовить».
2. **«Ты устала не от готовки»** — наезжает на hero. Сад: луг с маками, ромашками, космеями, базиликом и томатами, лианы по краям и сверху, падают лепестки. SVG рисуется кодом (`buildGarden` в `main.js`) по частям в свободное время, затем превращается в 6 картинок; луг поднимается из земли, лианы опускаются сверху, дальше всё покачивается на CSS. На телефоне текст лежит на матовой подложке, чтобы читался поверх лиан.
3. **Как это работает** — 4 экрана сменяют друг друга, фото выезжают «шторкой».
4. **Почему работает** — 4 цветные панели наслаиваются; на телефоне — карусель.
5. **Мини-игра «Не знаешь, что поесть?»** — кнопка крутит барабан с реальными рационами из канала (5 с калорийностью 1400–1800 и 3 фото рационов), он останавливается на случайном, под ним — «Решено: …» и ссылка «Хочу все 60+ рационов» (открывает выбор тарифа).
6. **Ленты «паста ✦ пицца… / не диета»** — canvas: буквы едут вдоль кривой «змейкой», ускоряются от скорости скролла.
7. **Что внутри** — шесть одинаковых карточек: фото → номер → заголовок → пояснение (3 колонки на десктопе, карусель на телефоне).
8. **Кристина** — две равные колонки по центру (фото на всю левую, текст справа) + цифры (−13 кг, −15 кг у Макса, 4 600+).
9. **Отзывы** — 9 лучших (на телефоне 7) плывут поверх большого заголовка и тают у верхнего края. Все 24 — в боттом-шите «Читать все отзывы», в конце шита — кнопка доступа.
10. Тарифы. 11. Вопросы. 12. Финал + подвал.

## Механики

- **Сцены на `position: sticky`** (без GSAP-пинов): прогресс скролла управляет анимациями → всё одинаково вниз и вверх.
- **Наслаивание:** следующая секция со скруглённым верхом выезжает поверх предыдущей (`margin-top: -100svh`). Уходящий экран чуть уменьшается и гаснет, только когда новый закрыл ~40% экрана. **Без blur** — текст читается, пока блок на месте.
- **Кнопка «получить доступ»:** в hero её ведёт JS (под заголовком → центр видео-карточки → низ). Внизу экрана она привязана через CSS `bottom` (класс `is-docked`), поэтому едет вместе с панелью браузера (Яндекс, Chrome, Safari), а не «телепортируется» после resize. В блоке тарифов прячется — там свои кнопки. По нажатию раскрывается как iOS-виджет.
- **Карусели на телефоне** (`.hs`): карточка чуть уже экрана, соседняя выглядывает справа — видно, что можно листать; у ленты запас сверху и снизу, тени карточек не обрезаются. Правило общее для всех горизонтальных списков.
- **Шапка:** своя композитная плашка с заметной тенью; уезжает, когда листаешь вниз (от 70 px подряд), возвращается при движении вверх (от 40 px) — без дрожания на мелких откатах и доводках.
- **Боттом-шиты** (меню, доступ, отзывы): ручка, закрытие свайпом вниз, крестик, Esc, клик по фону. Пока шит открыт, шапка на телефоне уезжает.
- **Без прелоадера:** страница видна сразу, маскот в шапке здоровается прыжком. Скрипты анимаций подключаются после первой отрисовки.
- **Типограф:** неразрывные пробелы после предлогов и союзов, перед тире, между числом и единицей — в разметке (`tools/typograph.py`) и страховкой в JS.

## Дизайн-система

- **Логотип:** маскот-ланчбокс + «Что поесть» шрифтом Lobster. Фавиконки и иконки — маскот (`assets/img/favicon*`, `icon-*.png`, `apple-touch-icon.png`).
- **Шрифты:** Noto Serif Display (узкий, 62,5%) — заголовки и акценты, курсив для выделений; Geist — текст; **Lobster — только название «Что поесть»** (логотип). Файлы свои (`assets/fonts`, OFL), подмножества кириллица/латиница, Google Fonts не нужен. `lobster-logo.woff2` содержит только буквы «Что поесть» (5 КБ вместо 74), `*-rub.woff2` — только знак ₽ (вместо latin-ext до 65 КБ ради одного символа). Если в тексте появятся новые символы вне кириллицы и латиницы — пересобрать подмножество (`pyftsubset`).
- **Цвета:** молочный `#F7F5EC`, крем `#EEE9DA`, глубокий оливковый `#2E3520`, оливковый `#5E6A3A`, шалфей `#CBD0B2`, лайм `#DCE7A9`, терракота `#96583F`, чернила `#1D1B14`.

## Производительность

- Анимируются только `transform` и `opacity`; анимированного `filter: blur` нет нигде.
- Слои, которые уменьшаются при наезде следующего блока, заранее вынесены в отдельный слой (`will-change`) — растеризуются один раз.
- Фото шагов и карточек декодируются заранее (`img.decode()`), у больших фото есть `srcset` (720/1280).
- Ленты: одна canvas, лента рисуется в кэш один раз, каждый кадр — только ~150 букв из атласа, и только пока блок на экране.
- Lenis (плавный скролл) — только для колеса мыши; на тач-экранах родной скролл.
- Первый экран не ждёт ничего лишнего: CSS встроен (при деплое), скрипты — после первой отрисовки, видео и картинки стикеров — после загрузки страницы, сад и ленты собираются по частям, когда до них близко.
- Сад после сборки — 6 картинок вместо ~1200 SVG-узлов: живой SVG утяжелял каждый кадр всей страницы, даже за экраном.
- Замер прокрутки (headless Chrome, телефон, CPU ×4): было 26–46 fps и ~30% кадров с рывками; стало 41–60 fps и 0–6% рывков. Рост сада при первом заходе: было 28 fps с рывками до 330 мс, стало ~44 fps без длинных задач.

## Как добавить отзыв

Скрин → WebP шириной 640 px в `assets/img/reviews/`, затем `<figure class="rsheet__item">` в шит (`#all-reviews`). Чтобы показать на странице — ещё одна `<figure class="rv__item">` в `.rv` (`--c` — колонка 1–3, `--o` — сдвиг вниз, `--r` — наклон; `rv__item--desk` — только на десктопе).
